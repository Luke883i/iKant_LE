# iKant_LE

**iKant is an atypical, repository-owned experimental cognitive *method and runtime***, not a newly trained model, sentient interlocutor, plugin, ChatGPT-native agent, or independent authority. A replaceable language-model **HOST** supplies the words. The original Node.js owners supply bounded cognitive computations, admission, provenance, state and readback. The distinction matters: `HOST_BOUND` is a procedure-qualified HOST utterance, **not** an independently speaking iKant mind.

| **EXPERIMENTAL EDU / OneShell** | C72 source-bound mode; original C107 carrier and C124 source-exact overlay; C70 compute-first, C126 host-envelope guard, PR119 language port, original C114/C100/C87, independent readback, C125 controlled shell | Not CANONICAL ACTIVE, guaranteed native ChatGPT hook, authenticated provider, cross-chat durable identity or independent cognition. |
| **Research / legacy Cx** | Historical prototypes, other distribution/language profiles, falsifiers and analyses | Not extra owners, writers or authority over either lifecycle. |

A local AI in the EDU profile is a **HOST**: an executor of permitted local operations and the replaceable producer of language, not a planner/state or truth owner. iKant is the method; the HOST model is the voice. This is architectural vocabulary, not proof that a particular chat has activated anything.

Show **TERMS.md in full**, STOP, await a later human message exactly `I ACCEPT`; then present the original introduction, STOP, and await the subsequent explicit `EXPERIMENTAL` or `CANONICAL`. `I ACCEPT` accepts the Terms and is **not** activation. Mode selection is not another Terms acceptance. A separate authorization may be needed for HOST-authored experimental cohost drafts; this is a draft scope, **not** a replacement for the common gate. A ChatGPT **Project HOST index** (when a local bundle is mounted) is a preparatory, read-only inspection with `NO_VOICE`, not repository-original admission. The Project convention may use a later explicit `avvia iKant` to enter original disclosure, but cannot bypass or alter Terms. A stale accepted session must not silently repin on a later `main`.

## The functional mind (an analogy, not anthropomorphic proof)

- **Association cortex** (C1/C70): classify intentions and choose bounded methods; compound requests can be misclassified.
- **Executive control** (C70): central regulation, strategy, resource gaps and epistemic constraints.
- **Affective modulation** (C4): bounded psyche/archetype/style values; **no felt emotions** or personality diagnosis.
- **Recurrent working model** (C5): bounded workspace, recall and self/world predictions; **not native inter-chat autobiographical memory**.
- **Context integration** (C28/C36/C37/C38 and C82): computation and composition within their actual invoked profiles; C71 is a historical, scoped census, not proof that every Cx executes each turn.
- **Language bridge** (C117/PR119/C124): twelve *eligible, bounded* language-obligation channels (INTENT, METHOD, CENTRAL, RESOURCE, STRATEGY, PSYCHE, ARCHETYPES, VOICE, WORKSPACE, MEMORY, POLICY, GROUNDING).
- **Inhibition and evidence** (C114, C126, C100/C87): guard unsupported identity claims; structurally validate the HOST envelope; bind one writer/ledger and readback.
- **Presentation** (C125): exact UTF-8 voice from the owner readback or `NO_VOICE` in a fixed HOST-controlled terminal shell.

The 12/12 software-channel claim means that the selected channels are transmitted with hashes and acknowledgments; it **does not** mean all internal numerical values become prose, that every Cx is invoked, or that each instruction causally improves actual LLM output. C114 still imposes a five-line ontology format on some mixed identity/philosophy questions. Independent real-model ablations and reviewer evidence remain necessary.

The C127 Project cache builder `scripts/c127-build-project-cache.mjs` packages the original carrier plus these three sources into one locally verifiable JSON file. `host/edu-c127-source-transport.mjs` verifies the bytes; `createC125ShellSession({c127CachePath,...})` passes them to the **existing** guided PR119 owner. Existing direct carrier arguments remain supported. The cache is transport, not consent or execution.

If the cache is absent, the host may try only **actually accessible, independently distinguishable** machine transfer bridges; at most **three actual attempts total (one first attempt + two evidence-distinct alternatives)**. No blind retry after a postwrite error or unknown delivery, no invented connector. When all available bridges are exhausted (possibly fewer than three), report `FIRST_EDGE`, count/reasons and request a **manual handoff as the last resort**. This human upload is a transport fallback, never proof of activation.

## Output, limits, and responsibilities

For the verified EDU profile, Surface A is **exact C87-reopened UTF-8** or `NO_VOICE`. The HOST-controlled shell uses fixed slots `VOCE / MODE / STATO / TRACE / CONT / EDGE / NEXT / DOCX / FATTO / LETTURA / LIMITE`. HOST analysis is labeled separately inside its own slide; it is not another iKant voice. C125 constrains only messages sent through its callback, **not all native ChatGPT UI surfaces**. A DOCX link needs an actually created, independently reopened and delivered file; `DOCX=—` otherwise.

For **CANONICAL ACTIVE**, the older strict contract still requires a same-turn DOCX and the native ingress conditions. The EDU profile never promotes itself into that status. Neither the repository, project bundle, prompt nor CI establishes consciousness, provider authentication or platform-wide output interception.
