## Re-analysis of the 24 October 2026 post-mortem

Proven proximate failure: original C72 receipt was not observed after `I ACCEPT`. A tool catalog search without matches does not prove that the Node owner is absent, unavailable, or uninstalled. Disallowed pre-HEAD metadata discovery is a sequence deviation; an owner-bound HARD receipt does not follow from prose. The manual ZIP fallback is **not** an admission mechanism. The first missing evidence is **the verified C72 owner binding/invocation within the actual Host carrier**. Native carrier delivery is independently unproved.

The existing preinstalled-only C72 gateway remains preferred. The smallest additional postaccept route is `host/project-c72-postaccept-reentry.mjs`: after a new, separate exact `I ACCEPT` it consumes the five pinned GitHub API document bytes and previously observed SHA-1s, verifies sequence and SHA-1, checks live HEAD, invokes **only** the original C72/v2 linked Terms acceptance and original introduction, validates both receipts and reports provenance as Host-claimed only. An unverified first-turn witness or changed source fails closed. This is a fallback **after consent**, never a new preaccept download permission. A generated hash is not a platform event authentication.

### Independent gates for product claims

Preinstalled gateway deployment, inter-turn handoff provenance, tool exclusivity, native event identity, independent readback and user-visible ChatGPT rendering require separate real-host tests. CI can certify software behavior only, not whether a particular user's ChatGPT UI routes to these functions. Until those are observed, `PRODUCT_NO_GO` remains.
