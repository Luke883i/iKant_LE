# C79 — Host-native Surface A consumption, source and delivery proof boundaries

## Target product statement
After a **later** exact I ACCEPT and still later exact EXPERIMENTAL mode choice, the genuine current human message must enter the C77/C78 real Node path, execute C70/C71/C73 and be displayed as its exact HOST-OWNED UNSEALED DRAFT in the ordinary ChatGPT assistant message. Native delivery and cross-turn persistence are **not** properties of an ordinary GitHub CI run.

## Mechanism and DoD split
1. `host/c79-native-chat-surface.mjs` requires a valid C72 mode selection and same source HEAD, C78 manifest, successful real C78 readback shape, Node exit status, C70/C71/C73 status, bounded non-sensitive input SHA-256, and exact C71 voice output SHA-256.
2. It produces a sealed-for-integrity (not signed, not host-authenticated) `C79_CHAT_PACKET_READY_NOT_DELIVERED` packet containing the unmodified UTF-8 voice, branding outside the voice, no DOCX URLs and truthful flags.
3. `scripts/c79-chat-frame-cli.mjs` consumes a C78 readback in bounded JSON-over-stdin and prints one typed frame. It does not itself render ChatGPT messages or persist a writer.
4. `compareC79SurfaceAEcho` compares exact bytes that the host may echo, returning `BYTES_ECHOED_NO_HOST_EVENT_ID`; a successful comparison does **not** mean ChatGPT recorded a native assistant turn.
5. Tests execute genuine C78 child Node invocations on a physically staged C77 capsule and 2,000 adversarial mutation checks (1,000 C78 readbacks plus 1,000 C79 packets). The runner is GitHub Actions Node20/22, not ChatGPT browser instrumentation.

## Source provenance and user-event boundary
C78's self-consistent manifest and file SHA values do not authenticate original GitHub read events. C79 conservatively retains `first_unclosed_edge=HOST_GITHUB_ORIGIN_AUTHENTICATION` and `next_unverified_edge=HOST_NATIVE_CHAT_SURFACE_A_DELIVERY`, even when it has a valid local echo. A model-authored object that fits the shape could pass, so do **not** treat `packet_sha256` as a signature.

An external host should supply actual evidence that the GitHub connector read approved blob SHA identities at pinned SOURCE_HEAD and that those exact bytes reached Node after the accepted EXPERIMENTAL selection. The ordinary ChatGPT assistant response can display the voice as a normal message only when the model has ACTUALLY executed and read back the C78 carrier on that same turn. A true native UI witness requires the host's own event/response instrumentation; C79 cannot create it.

## Counterexamples and hard stops
Never accept a made-up ACTIVE status, caller URL, fake source head, mismatched C72 selection, foreign human text, altered output SHA, altered voice, claimed native delivery, owner receipt or persistent state. Do not rewrite owner-sealed canonical ASCII. C79 is presentation glue for EXPERIMENTAL only.

## Next host witness beyond this PR
On a physically callable ChatGPT session, after the normal Terms→I ACCEPT→EXPERIMENTAL gate, source C77 bytes from pinned GitHub API, transfer into local Node, run C78, pass the same current message to C79, and put its `surface_a_chat.text` visibly in the ordinary assistant response. Repeat on a second real user message; report first missing physical edge instead of upgrading status. This test cannot be truthfully certified by a GitHub Actions run alone.

## Metric targets
Repository: 2,000 deterministic negative mutations, 0 authority escalations, Node 20/22 pass, no root-registry changes, no new privilege. Field success: `P(real human interaction -> kernel result in ordinary chat)` with a one-sided 95% lower confidence bound >=0.95 on prespecified independent real Project sessions; separate usability and continuity metrics.
