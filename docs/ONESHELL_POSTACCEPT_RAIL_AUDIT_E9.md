## Problems
1. Distinct projection layers (C125, S03, S05, HTML, text, thread candidate, compact) are not necessarily one persistent native UI. They may be re-rendered on every response.
2. Pseudopersistence must be defined as ORIGINAL C87 checkpoint verified across owner instances *within one chat*, not as provider-side widget persistence.
3. The Host can present ONE coherent six-slot rail from accepted C72 through source/READY and the original turn; it cannot synthesize A, edit the owner UTF-8, create receipts or replay a write after UNKNOWN.
4. Native HTML/SVG is a verified Host artifact, not a promise that the ChatGPT UI will render a permanent panel. Text fallback remains admissible.
5. `main` is the canonical source; each new session pins an immutable commit from main. A static SVG digest is an asset integrity check, not a PR source. Historical PR-labelled modules/fixtures in main are not by themselves PR-pinned runtime components. Runtime `refs/pull/N` sources are forbidden. Merge does not auto-update the installed Project prompt.
6. The existing `sourceHead===liveHead` rule stops on main drift within the chat. E9 deliberately preserves it; loosening it needs a separate policy decision.
