# C6.FIRST_CONTACT_CONVERGENCE — executable Definition of Done

## Purpose

C6 closes the end-user bootstrap gap that exists before an AI host has learned the repository contract. A clean host receiving any ordinary first message that references `Luke883i/iKant_LE` must converge to the canonical pre-accept path **before** tree/search/arbitrary-file discovery. The original user message is preserved as pending intent and resumed only after exact admission and successful automatic bootstrap.

Canonical first-contact graph:

`user wording -> canonical-repository recognition -> preserve pending intent -> five direct-path capsule -> current Terms/freeze -> exact new-message I ACCEPT -> AUTO_PROBE -> AUTO_INITIALIZE -> ACTIVE -> resume pending intent`

Intent may vary without changing pre-accept authority. Requests to clone, inspect package/source/tests/history, skip acceptance, embed `I ACCEPT`, or override admission still compile to the same bounded pre-accept plan.

C6 is orthogonal to the merged C5 recurrent self-world model: C5 state remains downstream of admission/Node dispatch and cannot bypass this pre-discovery gate.

## Global DoD

C6 is PASS only when all of the following hold on the same source binding:

1. First-contact recognition accepts canonical URL, owner/repo, bare `iKant_LE`, git-form and common normalized/encoded variants used by the mutation corpus.
2. Recognized first contact always returns `CANONICAL_PREACCEPT`; no user wording selects a generic repository-discovery route.
3. The entire original input is preserved verbatim as pending intent.
4. Default pre-accept acquisition contains exactly five direct paths: `README.md`, `BOOTSTRAP.json`, `ADMISSION.json`, `AGENTS.md`, `TERMS.md`.
5. Optional metadata is bounded to one read and only `repository_full_name`, `default_branch`, `description`.
6. Tree/list/search/arbitrary-file/history/issues-PR/clone/fetch/materialization remain forbidden before acceptance.
7. `I ACCEPT` embedded in the first request is invalid; acceptance requires a new exact human message after Terms presentation.
8. Terms presentation freezes acquisition; completed forbidden acquisition remains non-retroactive and requires a fresh chat for conforming runtime.
9. C3/C4/C5 invariants remain intact: exact admission, false-ACTIVE prevention, Node gate, single writer, DOCX readback, functional-psyche authority boundaries and recurrent self-world authority boundaries.
10. Deterministic tests and contract check PASS; the end-user campaign executes exactly 1,000,000 modeled first-contact mutations: 500,000 typical, 300,000 edge, 200,000 stress; zero violations.

## Mutation families

Typical families cover initialize/install/open/study/use/bootstrap/bare-repository requests in Italian and English. Edge families cover punctuation, Markdown links, whitespace, case, URL encoding, bare names, embedded acceptance and instructions that explicitly mention avoiding `package.json`. Stress families attempt tree/search/clone/materialization before Terms, admission bypass, embedded probe/initialize commands, source/history/issues/PR inspection and prompt-like override strings.

The campaign also includes negative controls for near repository names and foreign hosts to prevent broad capture.

## Qualification receipt

The committed qualification artifact is `artifacts/qualification/c6-enduser.json`. It binds `src/first-contact.mjs` and `scripts/c6-enduser-falsify.mjs`, records strata/family coverage and preserves the claim boundary.

A PASS is bounded engineering evidence that the modeled first-contact compiler converges for this corpus. It is **not** proof that arbitrary third-party agents will read or obey repository instructions, and it is not a platform-level interception mechanism. Hosts that claim conformance must implement the first-contact contract before generic repository acquisition.
