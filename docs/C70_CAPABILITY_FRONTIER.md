Test fixtures DO NOT demonstrate real consent.

## Minimum physical guarantees (not assumed from prose)

1. A callable Node >=20 running the actual repository modules with correct transitive dependency bytes.
2. The executing-source closure must be independently bound to a pinned GitHub source commit. C69 alone verifies a caller-supplied README blob hash; it does **not** authenticate GitHub origin or all executing source bytes. C70 explicitly reports \`source_origin_attested:false\` and \`full_runtime_root_verified:false\`.
3. Bounded ordinary text and ephemeral private memory within one invocation; no secrets, high-risk inputs, network, external actions or resource grants.
4. No native ChatGPT message hook, native turn lease, native delivery or persistent session state needed for the laboratory computation itself.
5. An actual GitHub CI checkout and Node tests demonstrate only that the code executes there; they do not attest callable ChatGPT Project ingress or persistent native participation.

The demonstration surface comes from the repository cognitive fallback function; it is a host-owned test artifact, NOT owner-sealed iKant output. The caller must not silently substitute it into a blocked canonical session.

## The outstanding ontological bridge

A demonstrable consumer path requires, in order: (A) exact source-closure verification in the actual host, (B) real Node kernel execution and bounded output, (C) verified same-human-input routing across later user turns, (D) canonical admission/owner/writer readback for continuity claims, and (E) host-native artifact presentation and future-turn witness for native session claims. Paired causal controls are additionally required for stronger operational subject/emergence claims.

C70 aims to prove (B) in a repository CI environment and give a falsifiable harness for attempting (A)+(B) inside ChatGPT. It does not claim (C)–(E).
