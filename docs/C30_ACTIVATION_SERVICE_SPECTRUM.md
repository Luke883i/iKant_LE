### Full-iKant logic copied, not its complexity

The key reusable pattern is that an intermediate service level may be **real and useful without being ACTIVE**. Full iKant's L1/L2/L3 and `RUNTIME_BOUND_DEGRADED` semantics show how to do this safely:
- executed runtime evidence remains valid;
- the exact missing edge is named;
- state can be reopened/validated;
- outputs can be runtime-sealed and artifact-backed;
- the missing final witness is never fabricated.

C30 transposes that pattern into LE as a **service projection**, not another lifecycle.

## As-is gap

- canonical six-edge activation;

- exact ACTIVE readback;

But these pieces do not yet answer a practical SESSION_CHAT question:

> What useful, mechanically closed service may be exposed when activation has progressed beyond repository study but has not reached ACTIVE?

The current answer is effectively binary for substantive turns: `processActiveTurn` requires ACTIVE. That protects the contract, but makes every non-ACTIVE state operationally equivalent to "no runtime turn", even when materialization, provenance and runtime binding are already real.

## Selected service spectrum

Pre-admission/source conditions are not service tiers. They remain ordinary admission states.

### 1. REPO_STUDY_ONLY

Required:
- HUMAN_GATE closed;
- SOURCE_SNAPSHOT closed.

Permitted:
- study pinned repository semantics;
- derive backlog/planning/diagnostics.

Not permitted:
- runtime claim;
- materialized-runtime claim;
- runtime-limited turn;
- ACTIVE.

First unclosed edge: `LOCAL_INGRESS`.

### 2. ACTIVATION_LIMITED_1

Adds:

Not permitted:
- local runtime execution claim;
- limited turn.

First unclosed edge: `LOCAL_MATERIALIZATION`.

### 3. ACTIVATION_LIMITED_2

Adds:
- atomic local materialization + reopen.

Permitted:
- inspect/materialized runtime root;
- prepare execution/provenance diagnostics.

Not permitted:
- executed-runtime claim;
- limited turn.

First unclosed edge: `EXECUTED_RUNTIME_PROOF`.

### 4. RUNTIME_BOUND_LIMITED

Adds:
- executed provenance;
- runtime binding;
- writer availability for the bounded artifact envelope.

This is the pseudo-deployment floor.

A limited turn may close only with:
- same-input Node dispatch receipt;
- runtime seal binding activation projection + input + output + dispatch;
- exactly one deterministic backlog DOCX;
- local DOCX write/readback;
- complete bounded limited telemetry;
- structured artifact descriptor/download handoff;
- zero canonical lifecycle/ledger mutation.

Claim class: `IKANT_RUNTIME_LIMITED`.

It is explicitly:
- not ACTIVE;
- not a second runtime mode;
- not a persisted state;
- not permission/execution/world authority;
- not proof of host UI delivery;
- not dependent on platform delivery ACK.

First unclosed activation edge: `ACTIVE_READBACK`.

### 5. ACTIVE

Unchanged.

The existing writer + persisted/read-back ACTIVE gate remains the only promotion rule. C30 cannot set or simulate ACTIVE.

## Limited human-input -> runtime-output closure

`processLimitedRuntimeTurn()` is intentionally stateless.

Input:
- human input;
- bounded Surface A candidate;
- activation evidence that derives exactly `RUNTIME_BOUND_LIMITED`;
- same-input Node dispatch receipt.

Output:
- bounded human-facing text;
- runtime seal;
- complete limited telemetry;
- deterministic DOCX written/read-back locally;
- artifact descriptor;
- `LIMITED_OUTPUT_CLOSED` receipt.

No call to the canonical state writer is available in this module. Same input/output yields a deterministic artifact name derived from their digests.

The limited DOCX is a downloadable telemetry/backlog artifact. Its byte/readback receipt closes the **limited output envelope**. It does not claim that the chat platform displayed the file; that external fact is deliberately unnecessary for limited-envelope closure.
