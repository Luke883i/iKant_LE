# EDU bootstrap first-best Pareto frontier: C78 -> C107 -> C72/v2 -> P1

**Scope:** Host engineering, authority=0, no new original owner. PR #176 laboratory. This is a finite, conditional software-path proof, NOT a guarantee of ChatGPT provider tools, 10,000 model calls, EDU activation, native event identity or persistent C135 worker.

## I. Is #176 sufficient?

No. The original #176 adds a local-file carrier and prompt hints, not a physical mechanism guaranteed present on every ChatGPT Host. A **field** bootstrap still requires: (G0) five ordered original first-contact SHA witnesses and Terms; (G1) distinct exact I ACCEPT; (G2) original eight pinned GitHub bytes plus independently verified cold seed physically reaching Node and read back; (G3) original C72 receipt plus COMPLETE original introduction; (G4) a separate exact EDU turn with original C72 mode selection; (G5) HEAD/TREE/critical prompt contracts preflight; (G6) original source materialized and independently reopened through Git TREE, original extractor and loader; (G7) original C135, unique C87 writer, C125/S03, languagePort and same live worker across real turns; (G8) actual host surface delivery and closing sequence. #176 cannot certify G1/G3/G4/G7/G8 through CI.

## III. Bounded first-best / Pareto contract

For a fresh consent turn, compare ONLY actually witnessed alternatives. Hard feasibility: exact prior first-contact source/terms witness, still-matching HEAD, new I ACCEPT, Node >=20, GitHub transport (except separately witnessed Node HTTPS), original C72 not invoked/unknown, pinned source bytes, SHA and readback. The policy `host/project-c72-transport-frontier.mjs` is advisory; an OBSERVED carrier means a genuine callable, physically verified carrier in the *current* Host, NOT merely both tools listed.

| Carrier | Feasibility | Original owner consequence |
|---|---|---|
| CALLBACKS | A real GitHub request callback callable inside Node | Run original C72 once, receipt + full intro required |
| NODE_HTTPS | Real Node HTTPS GitHub proven, no DNS error | GitHub content API pinned; original C72 |
| HOST_PACKET | A bounded direct Host -> Node stdin source packet really transferable | Eight verified sources + original seed; original C72 |
| HOST_FILE | GitHub connector + Node shared file tool actually transfers SHA-checked private files | Ten source/script transfers at cold start, 8/8 stage, seed original C72 |
| POST-EDU original ZIP | Original selection validated, Node ready, source absent/partial, explicit post-mode manual route | User may download original pinned source ZIP; independent TREE and extractor/loader checks precede original C135 |

The bounded metric `C72_MODEL_COSTS` is **normative, not empirical**: [Host copy count, sequential effects, external dependency burden]; CALLBACKS [0,2,0], NODE_HTTPS [0,1,1], HOST_PACKET [8,2,0], HOST_FILE [9,10,0]. The frontier eliminates strictly dominated candidates from the currently observed feasible set; ties use a deterministic original-source-first order. Numbers abstract away bandwidth, provider configuration, API limits, operational UX and failure probability. Consequently this is a Pareto-minimal policy **within the four predeclared alternatives and this metric**, not a proof of global software-optimality or unconditional full EDU reachability.

If a carrier is only CALLABLE_UNTESTED, plan a one-shot **non-owner physical probe** first, recording the real put/send/readback. An unobserved capability must not become an EXECUTE claim. After an UNKNOWN owner outcome, STOP; no blind carrier fallback or receipt replay. If all carriers are truly unavailable, the feasible set is empty and there is NO bootstrap theorem.

## IV. Full pathway and human download boundary

`ORIENTATION 5 SHA -> exact I ACCEPT -> observed physical carrier (try Host-assisted if Node HTTPS unavailable) -> 8 Git blobs + verified stager/seed -> original C72 accepted/full introduction -> STOP -> new exact EDU -> original EDU selection -> HEAD/TREE/critical prompt preflight -> original source already present OR verified GitHub -> Node materialization OR explicitly requested pinned ZIP after EDU -> independent ZIP extraction + Git blob/TREE equivalence + original loader -> original C135 languagePort + C87/C125/S03 same-session readbacks -> witnessed Host delivery.`

**Never require human upload to solve P0**. Manual download is P1, strictly after original EDU selection. The user only receives the exact immutable ZIP URL and can attach the original code; never a generated bundle. Source ZIP presence alone is NOT mechanical verification.

A prompt instructs the Host to attempt a transfer; it cannot grant filesystem access, instantiate a provider callback, preserve a Node process across messages, force native delivery, or substitute missing user events. Runtime/source-lock epoched receipts must not migrate from a PR candidate or fixture. If a specific Host tool cannot move 56KB BOOTSTRAP bytes, record that physical tool/size limit; do not infer no bridge exists globally.
