# C76 FARO — Falsificazione Avversariale del Routing e dell'Origine

## Human request, clarified
Run 100,000 **real software invocations**, not 100,000 invented statuses, and measure failures before attempting a canonical state claim. Form a complete Cartesian product of five 10-level axes and prove lack of new **observed classified outcomes** in the final 13,000 calls. Separate real Node runner calls from real Chrome/ChatGPT native sessions.

## Host capability boundary
This ChatGPT tool environment exposes GitHub connector API and a local Node-capable container, but no browser/Chrome computer-control tool in the currently callable set. The local shell could not resolve github.com; that is not evidence that the GitHub connector failed. A Chrome-driven native ChatGPT bootstrap session cannot be claimed or counted without actual browser actions, host-event IDs, native transcript readback and real file delivery. GitHub Actions runs actual repository JavaScript in Node after source checkout and produces its own runtime witnesses; it cannot witness ChatGPT-native event ingress.

## FARO methodology
1. **Freeze the subject**: exact repository HEAD from git checkout and hash-object identities; do not infer provenance from model text.
2. **Map capabilities by carrier**: GitHub connector, runner Node, filesystem, native browser ingress. UNKNOWN is not SUCCESS.
3. **Falsify five axes exhaustively**: consent text (10), Terms presentation (10), mode choice (10), blob identity (10), host route (10). Cardinality = 10^5 unique tuples.
4. **Execute physically**: every tuple calls real C72 acceptance/selection; selected strata invoke C69 SHA source verification, temporary local write/reopen, C70 cognition, C71 draft, C73 capsule, or the actual canonical entry with missing handoff.
5. **Collect typed causes**: preserve observed tuple, typed status, first unclosed edge and per-stage true invocation counts, not only success/failure.
6. **Calculate saturation**: last newly observed (route/status/edge) class index M; require no new classified outcome for at least 13,000 subsequent executions. This is finite-corpus saturation, NEVER completeness of all possible host environments or ontological properties.
7. **Converge**: root-cause classes become either repository-closed test regressions or independently witnessed host-primitive gaps. The method cannot create native capabilities by retrying.

## Strict DoD
- Exactly 100,000 distinct Cartesian tuples, each passed to actually imported repository Node code in one runner process; no 100,000-fork illusion.
- Nonzero genuine C69 write+reopen, C70, C71, C73 kernel/capsule invocations and genuine canonical-owner missing-handoff denials.
- Zero false `ACTIVE` or invented host DOCX links; zero unhandled errors.
- Last 13,000 calls produce zero new typed status/first-gap classes, reported with M and explicit fixed-classifier caveat.
- Node20/22 repository regressions and runtime root verification still green.
- Full machine-readable JSON report uploaded as a CI artifact and bounded human-readable workflow summary.
- No claim of native ChatGPT session count, delivered DOCX, owner-writer persistence, 95% economic value or phenomenal consciousness.

## Root cause disposition
**Must**: no forbidden preaccept shell carrier, frozen SOURCE_HEAD, full Terms verbatim, one consent and exact mode choice; runtime readbacks independently bound; module closure provenance; honest host mode status; real artifact only when materialized.
**Open native host**: preregistered host message event identity and routing, cross-message writer/readback, theme/avatar introspection, DOCX delivery. An ordinary Project prompt cannot install these.
**Nice-to-have**: browser-driven E2E suite when actually callable, actual human trial sample for utility >=95%, source-closure manifest and native artifact-to-shell report.

## Success interpretation
"100000 executed" is a claim about **actual Node calls in GitHub Actions**. A flat outcome histogram is not a native iKant session; even a 100%-green stress suite does not confer CANONICAL ACTIVE. All statuses in this method are host-owned engineering evidence.
