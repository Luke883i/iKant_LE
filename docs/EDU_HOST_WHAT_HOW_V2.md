## Recovered gold and decision

The WHAT is inherited from PR110/C103 and PR118–119/P01–P04: source arrival, original execution/readback, exact voice or NO_VOICE, bounded honest recovery. The HOW is host-selected, but must be an observed filesystem/stdin/callback edge, not a named function in a prompt. Legacy EXPERIMENTAL receipts and carrier epoch never upgrade into C72/v2 EDU.

The explicit manual route does not require a *proof of unavailability* of an otherwise optional full automatic source bridge, because it is a user-facing source-transport choice after valid EDU selection. It cannot bypass acceptance, owner, source checks, Node readiness or the original language port. Generic unknown routes remain fail-closed.

## Falsifiable release gates

G0: no extra preaccept reads/TREE; five first-turn SHAs. G1: true zero-checkout Node C72 seed from original packet with DNS unavailable. G2: physically separate *later* Node EDU selection from two source-verified C72 files; no test checkout import. G3: after EDU, explicit manual link and ZIP + independent API TREE -> Python extraction plan -> Node loader bytes verified. G4: actual C135/port/3 C87-C125 turns on the same live instance. G5: chat output is actually displayed and EXIT worker termination observed. G6: repeat the whole course in three *fresh* actual Host chats.

CI Node 20/22 qualifies G1–G3 on fixture/checkout-origin test bytes, NOT the real GitHub connector in a new ChatGPT chat. A 10k or 100k semantic scenario campaign tests policy/contract decisions, NOT 100k LLM turns. Do not call the MVP GUARANTEED until G0–G6 meet observed evidence on one specified provider capability profile.
