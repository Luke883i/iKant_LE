# C101 hardening | bounded host-local gold composition (authority=0)

## Intent clarified
Make the middle tier **physically executable in local Node** and strengthen its
voice gate with existing repository functions; *do not* install ChatGPT hooks,
reopen canonical deployment, synthesize owner receipts, or edit Project prompts.
C101 remains one invocation per human turn, stateless beyond that invocation.

## Censused golden components
`node scripts/c101-reuse-census.mjs` enumerates every `.mjs` file in `src/`
and `host/`, content-hashes them, extracts declared exports and enumerates a
closed curated admission table. Entries outside the table are **inventoried,
not automatically admitted**. `C4` psyche, `C5` self-world, dispatch,
`C82` response family and `C83` classifier already run *indirectly* through
`C70/C71`; there must be no second classifier, writer or duplicate voice
engine. Existing `C98` supplies `isC98JSONDataTree` for the untrusted
optional rubric envelope; **only that pure guard is imported**, not the C84
carrier owner. Existing `C89` qualifies optional caller-pinned bounded phrase rubric
without independent semantic review. `C86/C87/C91/C92/C95/C98` are excluded
from this tier because their owners require stronger or different receipts.

## Current physical carrier
Local exact-source Node checkout plus explicit `--ndjson` is a **real stdin
carrier** when a host spawns the CLI and supplies lines. A line produces one
schema-bound C101 result and `verifyC101Readback`; a failed input cannot promote
ACTIVE and does not terminate the reader for a later line. Run:

`node scripts/c101-local-machine-cli.mjs --ndjson < messages.ndjson`

The existing one-shot stdin CLI remains unchanged by default. Neither mode
makes the ChatGPT Project environment intercept messages or transports the
repository to Node. For native ChatGPT per-turn operation an integration must
supply actually installed module-graph bytes, a genuine host dispatch hook,
current event and exact output presentation. No claim from a text prompt.
