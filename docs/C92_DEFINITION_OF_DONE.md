2. Two **real** HTTPS Responses API calls (generator and reviewer), each with distinct configured keys and distinct model names; Node observes response IDs, TLS peer verification and hashes of raw responses. Separate models are not independent organizations or a proof of factual entailment.
3. Candidate must pass unchanged C91 schema and evidence check. Review must pass unchanged C91 reviewer. Separate deterministic C92 verifier checks exact input/head/candidate and reviewer readbacks, source IDs and hard forbidden claims, rejects replay, unexpected keys and missing evidence. Independent checker is not a second model.
4. C92 owner approval occurs only inside executable same-turn production function. One exact UTF-8 Surface A string is rehashed, fsynced, reopened and compared. Host native presentation still UNKNOWN.
5. No credentials in receipts, no open endpoints, no unapproved actions; no ACTIVE/DOCX/phenomenology claims.
6. Audit must include real provider-e2e execution and at least 50 independent model turns before production promotion. No real provider call means status UNPROVED.
7. C29 36 atoms source-bound checker and C72 >=500 tasks >=50 sessions >=20 users Wilson lower bound >=0.95 require separate qualification; not implied by this slice.
