# EDU HostBound MVP — decision record, proof gates and stop rules

Baseline: main@7b19065954963487ac2e49e3dee05e3ac2a227a1 (PR #172). This record is engineering guidance, authority=0, not a C72 admission receipt or a release declaration.

## Product target and the meaning of guarantee

Deliver a qualified EDU HostBound session in a specified actual Host environment: first-contact orientation; distinct I ACCEPT; original C72/v2 acceptance and complete introduction; later distinct EDU with original mode receipt; verified full source; one live C135 worker with a callable language port; three non-replayed human turns with original C87 independent readback and C125/S03; truthful OneShell text/verified brand projection; safely acknowledged two-message exit. A successful build or fixture never proves native ChatGPT support.

**Guarantee scope:** repeatable observed behavior in the nominated Host environment and explicitly tested session/lifetime envelope. Without an actual Host byte carrier, human input handoff, live language port and delivery boundary, FIELD_NOT_ATTESTED. No promise of provider-native UI, arbitrary client portability, authenticated provider origin, persistent process across chats or C59 ACTIVE.

## Decisions: global / intermediate / local

Global: prioritize EDU HostBound with original owners C72, C135, C87, C125 and unchanged C59 boundary. Reject both universal-ChatGPT promises and prompt-only bootstrap claims. Native client integration is a distinct future release.

Intermediate: prefer Host-observed GitHub API bytes -> one explicit Node carrier, since Node outbound DNS has been observed to fail in field. Choose exactly one callable connector callback or verified packet/staged ingress *before invoking C72*. A P0 eight-file kit is a narrowly permitted after-I-ACCEPT contingency, not a Project bundle or a preconsent request. An API success in one tool and a Node version in another are not a bridge.

Local: remove the preaccept TREE requirement from the optional preinstalled OneShell orientation coordinator. FIRST_CONTACT needs exactly HEAD and five blob SHA witnesses. A Git TREE is acquired only in the separate post-mode source materialization path. Preserve source SHA checks and fail-closed mode/owner rules.

## Anti-loop invariant

Every automated NEXT must have an installed Host performer, a physically observed effect and independent owner/readback evidence. A graph edge with only a named repository module is OPEN. A post-merge green CI suite cannot close any Host field edge. An UNKNOWN write/send result requires read-only reconciliation, never replay. Do not publish another workaround PR that merely renames a blocker.

## Release slices (each is an independently stoppable gate)

1. G0 SOURCE_CONTRACT: fix preaccept TREE conflict; tests use NO TREE (including trap getters), original C72 only, source manifest and strict five-doc preaccept. This PR closes only G0 software.
2. G1 P0_EXECUTOR: one cold Node process receives original seed and eight verified Git blob bytes, with DNS disabled and no checkout. Output original acceptance and full introduction; negative corruption/HEAD/witness/ambiguous owner cases.
3. G2 FIELD_C72: fresh real Project chat, first-turn five SHA witness, exact later I ACCEPT, real physical transfer to same executor, original accepted/introduction with observed output readback. This must be tested on the actual Host, not a GitHub Actions fixture.
4. G3 FIELD_MODE: a different later human EDU message re-enters the original selection owner from verified staged originals or a proven surviving process, without checkout/test imports and without repeating consent. Demonstrate code/receipt continuity after the cold seed cleanup.
5. G4 FIELD_EDU: post-mode HEAD/TREE/blob source closure, real callable languagePort, same C135 instance, three distinct nonce turns, independent original C87 reopen and C125/S03 exact UTF-8 readback. Do not claim delivery if only stdout/in-memory.
6. G5 FIELD_PRESENTATION: observe the complete output in the actual chat destination. Preserve original A bytes, six slots, canonical SVG only when verified else TEXT. Verify two-message EXIT and worker termination, including unknown-outcome denial.
7. G6 RELEASE_CANDIDATE: reproduce from three independent fresh chats in the same qualified Host profile; record actual installed prompt equivalence where accessible, explicit tool capability inventory, rollback, failure log, recovery semantics and limits. Only human product decision may promote to MVP_EDU_HOSTBOUND_QUALIFIED.

## Release proof ledger

Every gate must record: source_commit, git_tree where allowed, source SHA-1 blob identities, original owner function/receipt digest, Host-carrier identity, real process invocation and readback, observable output destination, fresh test session and negative-case outcome. Labels: SOURCE_PASS, ISOLATED_EXEC_PASS, FIELD_PASS, UNKNOWN, FAIL. Missing proof => UNKNOWN, not PASS. CI-only positive examples must never be accepted as FIELD_PASS.

## Alternative decision notes

Prompt-only: rejected as physically inert. Node-direct HTTPS: optional only when field-observed, not reliable primary where DNS failed. Preloaded full Project bundle: rejected as a universal contract; previous apparent success was environment-dependent. Connector->Node packet/stage: primary because observable, bounded and testable in an authorized Host. P0 manual narrow kit: bounded fallback after acceptance and only when actual upload/staging is supported. Native MCP service: potentially stronger future delivery, but requires deployment/authentication and cannot be simulated by a repository patch. Native UI/avatar is outside Host authority.

## Hard stop / rollback

Do not merge or release a claim beyond its tested gate. Stop and revert a candidate if it introduces preaccept TREE/file downloads, owner substitution, duplicate C87 writers, fabricated A, automatic source repin, retry after UNKNOWN, undocumented user gateway debugging or a green-CI->PRODUCT_GO promotion. Do not repin an active runtime session merely because engineering HEAD changes.

## This first slice

Changes only repository-owned orientation coordination and explicit unit/falsification callers to require no TREE, plus this release record. Original C72 and EDUs remain untouched. This is not G2 C72 FIELD_PASS or a functioning EDU MVP. The next real milestone must be a witnessed P0 Host transfer, not another planner.
