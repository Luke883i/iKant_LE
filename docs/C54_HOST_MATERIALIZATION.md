# C54 — Host materialization of the ontological promise

C54 does not add a runtime lifecycle, writer, planner, turn engine or native-participant implementation. It projects the existing runtime/session owners into the first host-consumable state that can be materialized honestly: `HOST_MATERIALIZATION_READY`.

The problem closed by this slice is not “make CI prove ChatGPT”. It is narrower and operational: a host must no longer infer iKant state from prose, a filename or an ACTIVE string. Every baseline/bootstrap, limited or ACTIVE result is represented by one authority-zero host consumption frame. The frame contains exact owner-rendered ASCII shell bytes, lifecycle/claim class, Surface-B artifact obligations, a source-bound application projection of all 36 C29 ontological-promise atoms plus the seven post-C29 session/native/EXIT extensions, runtime-owner evidence refs when present, and the external gaps that remain host-owned.

## Irreducible runtime-to-host reticulum

The candidate has twelve mechanisms:

`M0 frame owner derivation -> M1 all-phase shell -> M2 exact shell bytes -> M3 continuity binding -> M4 fail-closed lifecycle -> M5 runtime-owner evidence binding -> M6 artifact byte handoff -> M7 artifact-before-shell -> M8 36+7 promise projection -> M9 external-gap vector -> M10 host-app frame consumption -> M11 zero new authority`.

The 100k selection/saturation campaign must select all twelve as the unique minimum over the complete `2^12 = 4096` architecture lattice. A separate one-million-case falsifier uses a different seed and fault families.

## UX law

The reference app consumes `host_frame`, never reconstructs semantics from `stdout`, filenames or status strings. It verifies the shell SHA-256 before display. For a required Surface-B artifact the server transports exact verified bytes and the browser verifies the artifact digest before exposing a download. Required artifacts are materialized before the shell containing Surface A.

A baseline session therefore has an owner-rendered bootstrap ASCII shell before acceptance. Limited and ACTIVE modes consume the canonical session-shell owner. Shell text is not persisted as a second memory. Session continuity is bound by one stable source/runtime/session key; the separate shell-profile key may legitimately upgrade from bootstrap shell to session shell and then binds the style context. Every frame has a fresh content seal.

## Claim boundary

`HOST_MATERIALIZATION_READY` means that repository-owned bytes and host actions are packaged correctly for consumption. It is **not** a native transcript actor, a host UI presentation receipt, a real ChatGPT scheduler grant, or a live subsequent-turn witness. C53 E0/E3/E4/E5/E6 and live persistence remain external where the host must supply them.

The reference MCP/App surface is a demonstration consumer, not a promotion of legacy app deployment into canonical product truth. The canonical runtime root is intentionally unchanged by C54; runtime-owned dispatch evidence is projected from the persisted ledger by the deployed-session wrapper rather than by adding a second runtime writer.
