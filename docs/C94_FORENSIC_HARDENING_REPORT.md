## Product architecture and unavoidable dependencies

The correct product is a **preinstalled host adapter**, not a larger project prompt. It needs 1) an authorized GitHub-API HTTPS source bearer, 2) an Actions read grant and outbound network in Node, 3) an installed source-pinned C90–C94 runtime, 4) two distinct actual inference provider credentials, 5) an independent semantic-entailment/evidence assessor, 6) a platform-native ChatGPT ingress and delivery hook with authentic event readback, and 7) a qualified writer if canonical continuity is pursued. These are capabilities, not strings that an LLM can manufacture.

The cold source bootstrap has a chicken-and-egg issue: the automatic downloader itself has to reside in an already installed, callable host integration. A repository script cannot install itself into ChatGPT Projects simply by being described in Markdown.
