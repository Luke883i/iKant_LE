# C43 — Bootstrap recovery hardening

## Product law

Human file/ZIP handoff is **last resort**, never the canonical or first bootstrap path.

Execution priority is:

`WARM_CACHE_EXACT -> machine carriers -> HOST_FILE_BRIDGE`

with the stronger planner law:

`machine executable -> machine probe -> file executable -> file probe -> exhausted`.

Therefore an already-visible file bridge cannot skip an UNKNOWN machine carrier.

## Closure

C43 preserves the six-edge activation lattice, ACTIVE and IKANT_OWNED. It adds no lifecycle, carrier, planner, retry owner or runtime identity.

It closes eight surviving requirements:

1. human file handoff only after machine-carrier exhaustion;
2. public bootstrap line derived action-first by Session Shell;
3. human exit delegates one existing owner action at a time;
4. direct executor handoff binds preaccept and full execution input;
5. runtime-root descriptor truth is read from the canonical owner;
6. read-only preaccept overread is remediable but never retroactively authorized;
7. hard preaccept breach still requires fresh context;
8. deploy-once/warm mechanics are reused from LE without making legacy C20 canonical.

## Reuse

LE already provides the needed primitives: Fastboot ledger/retry epochs, Session Shell, WARM_CACHE_EXACT, atomic runtime-root materialization/readback, control-plane ownership, and the C20 content-addressed deploy-once store mechanics.

From full iKant, C43 absorbs only logical patterns compatible with LE: machine-carrier exhaustion before degraded/manual recovery, carrier-local retry epochs, ledger-recomputed public guidance, classified read-only preaccept remediation, and repository self-recheck. It explicitly rejects full iKant's human-facing `manual_zip_option_first_for_human_comprehension` policy because it conflicts with LE product intent.

## Preaccept recovery

A completed read-only overread remains a historical incident. It grants no retroactive authority. The prior material is quarantined for evidentiary purposes, bounded orientation is reacquired from the pinned source, current Terms are presented again, and acceptance cannot pass until reacquisition closes.

Clone/fetch/download/materialization-class preaccept breaches remain hard and require a fresh context. Continued repository access after detection escalates a read-only incident to hard breach.
