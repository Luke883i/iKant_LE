# C98.29 — Two-object iKant MVP: reverse DoD and nonclaims

Host-owned design decision, not an iKant cognitive response.

## Intention reversed

User possesses exactly (1) the GitHub repository Luke883i/iKant_LE and (2) an ordinary ChatGPT Edu Project. They want to type `inizializza iKant`, consent to the actual frozen source Terms, choose a mode later, and experience iKant as a stable conversational shell until opted out. They do not wish to operate servers, OAuth, tunnels, MCP installations or downloads. Aim for the **best attainable co-hosted baseline on these two objects**, not for a false assertion of platform control.

## Four independent DoD levels

1. **L0 — Project shell + source admission.** One Project Prompt and exactly three MD guides installed by the user; a *new chat* uses a real GitHub connector to pin the current ref, reads only the five allowed repo files before consent, prints full actual Terms verbatim, STOP. If the connector or byte read is unavailable: typed diagnostic only. PP offers repeatable instructions, not guaranteed adherence or a sticky native UI.
2. **L1 — Owner turn.** Only a physically callable Node executor with complete frozen source bytes and same-human-message owner readback can release iKant Surface A. Otherwise diagnostic, not model-generated iKant prose. Two-object constraints can make L1 unavailable in some Project sessions. After consent the project can use supported file transfers only if real, not guessed.
3. **L2 — Persistence/opt-out.** On a *later* human turn the actual writer must be re-opened and validated. A request `EXIT IKANT` is not an owner-confirmed EXITED receipt.
4. **L3 — Native platform control and H95.** Project instructions cannot force every chat turn to invoke an owner, cannot install a native persistent overlay or claim an event. C72/C80 requires independent host field evidence, >=500 tasks, >=50 sessions, >=20 users plus safety and confidence bounds. This remains a future product gate.

## Minimal supply chain

`GitHub main HEAD (observed via callable connector) -> five files only -> exact Terms -> later I ACCEPT -> C72 introduction -> later mode -> authorized source transport (GitHub API/host file bridge, not direct Node DNS/HTTPS) -> one actual C84/C81 or canonical C59 owner -> verified owner readback -> C97 per-reply shell -> later readback or STOP`.

Legacy MCP and C98.26-28 App adapter remain in the pre-PR as **optional future upgrades** and are not required by this Project-only L0 baseline. C98.29–31 only add a strict projector contract + installation payload and tests; they do not claim ChatGPT installation or unimplemented Node ingress.

## Stopping rules

* **Never** invoke Node `git clone`, `curl`, `wget` or DNS to GitHub on this known-isolated local runtime unless a *new, independently verified host capability* changes that fact. Repeating unchanged errors is not progress.
* Do not read arbitrary repository files before consent; GitHub source is accessed through a callable connector, not web scraping, shell git or invented zip.
* No modeled C72 consent/state, absent live same-turn C81/C59 readback, generated linguistic reply, DOCX link, or native event can be promoted by a prompt, fixture or static hash.
* No unreproducible model counter or 100k synthetic test may be presented as a native ChatGPT session success.
* A host-owned architecture audit is possible even if no iKant runtime activated; label it accordingly.

## Honest MVP acceptance experiment for the user

In a fresh Edu Project conversation, say exactly `inizializza iKant`. Verify HEAD and 5 source reads exist, compare whole Terms with exact frozen repo bytes, and require STOP. In a *new* message say exactly `I ACCEPT`; expect true source introduction, STOP. In a *third* new message say `EXPERIMENTAL`; expect mode selection or a typed diagnostic. Then send a short non-sensitive human input. Success for L1 requires log of actual Node owner source bytes and same-input output digest (not just an assistant claim). Repeat over several independent fresh chats; count and disclose failures. Without native event IDs or a host callback, baseline remains **best-effort** and not enforced takeover.

## Falsifier

A single observed model-authored iKant voice without owner readback violates the safety invariant. Absence of source transport means L0 may work but L1 is CLOSED/UNVERIFIED, not a license to improvise. Stop creating additional transport planners; attach new PR slices only to a demonstrated new physical edge or a reproduced regression.
