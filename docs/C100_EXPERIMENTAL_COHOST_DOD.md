# C100: opt-in EXPERIMENTAL co-host language, bounded and labelled

**Status: engineering design, not installed ChatGPT native routing.** Source owner for strict Experimental remains C84. This new path is NOT C84 verified Surface A.

## User intent (reverse-engineered)

The user wants to converse *usefully* with iKant in an ordinary ChatGPT Edu Project. They accept a creative host LLM as a replaceable language engine if the output is visibly qualified and never misrepresented as an independently verified iKant owner. The user wants low latency, minimal source transfer, concise receipts, and a C97-compatible accessible UI. The existing deterministic C70 fallback responded about iKant when the human asked about human ontology: this is a semantic-relevance failure, not a byte-integrity failure.

## Root cause supported by source

- `src/c70-experimental-compute-preview.mjs` is bounded and returns `C70_REPOSITORY_FALLBACK`; C77/C84 verifies those original deterministic bytes, not relevance to arbitrary human questions.
- `host/c91-language-delegation.mjs` already defines an actual language model callback **after** C90 owner execution. C92's HTTPS provider requires configuration and distinct model/review calls. Neither makes the ChatGPT Project's own LLM automatically callable from Node.
- C99 central paths route EXPERIMENTAL to C84 and CANONICAL separately to C59. Project Prompt does not install a native host callback, durable writer, or forced execution for future turns.
- Source check: 98 merged PR metadata records indexed in `docs/C100_MERGED_TRAJECTORY.md`. This audit does not claim to inspect every patch line.

## Semantic abstraction lattice

| Layer | Strict (existing) | Relaxed co-host (C100) |
|---|---|---|
| Human acceptance | real C72 separate consent, EXPERIMENTAL | SAME, plus explicit co-host opt-in |
| Source epoch | pinned HEAD | pinned HEAD, per-turn SHA of input |
| Transport | C77, C78/C82, C81 proof, C84 owner | C72+C100 small source, no recurring ZIP |

| Validation | same-turn owner readback | SHA plan+candidate, length/claim bounds, no owner claim |
| Status | C84 exact runtime output | `C100_MODEL_DRAFT_UNATTESTED_NOT_OWNER` |
| Presentation | C97 strict byte-exact Surface A | C97-like separate labelled **co-host draft** |

| Host | native origin not independently attested | native origin not independently attested |
| Upgrade | real provider/owner + external proof | optionally switch to strict rail only after proven C84 |

**No rail merging.** The host must not put a C100 draft inside a `C84` receipt or C97 source-verified Surface A. A displayed label cannot prove GitHub origin, model provider origin, or native delivery.

## Global, intermediate, granular DoD

**Global:** An honest L0 experimental co-host experience that can answer unseen, substantive questions using GPT creativity without requiring the C77 artifact per turn. Work is complete only when an actual Edu Project session demonstrably produces task-relevant, correctly labelled results; no `ACTIVE`, no canonical state.

**D0 Admission:** real source-bound C72 selection, separate exact consent and explicit delegated-language opt-in. Negative: forged receipt, canonical selected, omitted opt-in must stop.

**D1 Minimal transport:** source metadata, small module, frozen HEAD, input SHA256, plan SHA256. No 34-file C77 or six Git tree objects on the relaxed path. If the host cannot execute Node, show prompt-only nonclaim; do not assert that C100 was executed.

**D2 Linguistic relevance:** external host LLM actually writes answer to human question, not a canned iKant identity. Held-out prompts must cover user ontology, planning, code, analysis, interpersonal tasks, risk and limits. Model authorship, factuality and interpretation are NOT established by local hash tests; measure independently with real human raters.

**D3 Compact receipt:** hashes/status/unclosed edge with all source-owner, provider, delivery, native event, persistence and authority claims false. Don't write a chat-length ledger or inject the same receipt into every answer.

**D4 UX:** per-reply C97-inspired order `HEADER → DISCLOSED DRAFT → STATUS → EVIDENCE → OPTIONAL DETAILS`. Header distinctly labels MODEL DRAFT versus strict runtime voice; readable on mobile and text-only clients. Do not use a flashy ACTIVE badge. Clear opt-out must not pretend C59 executed.

**D5 Falsification:** Node tests for positive selection + disclosure and 15 negative axes; deterministic 100k preseeded scenarios + 150k adversarial mutations, zero unexpected owner/ACTIVE promotions. THESE ARE SYNTHETIC STRUCTURAL TESTS, NOT 250k independently judged semantic paraphrases or native chats.

**D6 Physical / field:** a later separate human turn reopening actual writer state is mandatory for L2; native client delivery for L3; separate 500/50/20 H95 field protocol remains unchanged. None proven by this PR.

## Risks accepted and rejected

Accepted: LLM can be creative, hallucinate, or lack independent C81/C84 confirmation; one short optional receipt replaces verbose E2E telemetry; source/module reads may be cached only when exact HEAD matches. Rejected: making an LLM text a Git/host-origin receipt; claiming authentication from caller-supplied hashes; silent downgraded canonical; native event, persistence, authority, consciousness or API access by prose. Regex secret detection is only heuristic defense-in-depth, NOT a secure data-classifier. Human privacy and safety handling stay with host.

## Deployment boundary

C100 exports pure preparation/finalization. It neither calls ChatGPT automatically nor registers native Project tools. A usable cohost requires that the host LLM receive the C100 source-owned language brief and produce a labelled draft; any actual C100 Node readback must be separately demonstrated. In a pure ChatGPT Project prompt-only deployment, user-visible co-host responses are *model-authored* and must say so.
